# PMP — Project Management System

A simple Django app for tracking projects and tasks on a kanban-style board.

## Features

- Projects with descriptions
- Tasks per project with status (To Do / In Progress / Done), assignee, and due date
- Kanban board view per project
- Django admin for managing everything

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Visit `http://127.0.0.1:8000/` for the project list, or `/admin/` for the admin site.

## Project structure

- `config/` — Django project settings and root URLs
- `projects/` — app with `Project` and `Task` models, views, and URLs
- `templates/` — HTML templates

## Deployment (Render + Neon Postgres)

The app reads its database from a single `DATABASE_URL` env var (via
`dj-database-url`) and falls back to local SQLite when it's unset, so the
same settings work in dev and production.

1. **Database — [Neon](https://neon.tech):** create a free project, then copy
   its connection string (looks like
   `postgres://user:pass@ep-xxxx.aws.neon.tech/dbname?sslmode=require`).
   Neon's free tier has no expiration — it just autosuspends after 5 minutes
   idle and wakes on the next connection.

2. **App — [Render](https://render.com):**
   - New → Blueprint → point at this repo. `render.yaml` defines the web
     service, build (`build.sh`: install deps, `collectstatic`, `migrate`),
     and start command (`gunicorn config.wsgi:application`).
   - When prompted, paste the Neon connection string as `DATABASE_URL`.
   - `DJANGO_SECRET_KEY` is auto-generated by the blueprint;
     `RENDER_EXTERNAL_HOSTNAME` (set automatically by Render) is added to
     `ALLOWED_HOSTS` in `config/settings.py`.

3. Once deployed, create an admin user from the Render shell:
   ```bash
   python manage.py createsuperuser
   ```

Static files are served by WhiteNoise (`config/settings.py`), so no separate
static host is needed.
